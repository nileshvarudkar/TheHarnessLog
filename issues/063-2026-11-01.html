GitLab ships a permission-aware lifecycle graph so agents stop scraping context and start querying it

Blair Hayes, via forkast.news — “GitLab Orbit Puts a Shared Lifecycle Graph Behind Multiple Agents”

GitLab Orbit, generally available since October 15 on Premium and Ultimate, is a live, queryable graph spanning code, merge requests, work items, pipelines, vulnerabilities, and ownership — a “unified data layer” that GitLab Duo, Claude Code, Codex, or any other MCP-compatible tool can query directly, with no separate connector or ETL pipeline. The key design choice is that it's permission-aware: it mirrors nested groups, roles, and security-domain access rather than exposing one flat index to every agent. GitLab's own reported numbers — up to 45× fewer retries and 4.5× fewer tokens on the same tasks — are vendor-reported, not independently benchmarked, and a 19.5.3 patch already reverted some Orbit backports on the stable branch.

Why it lands for you A query layer that mirrors nested groups, roles, and security-domain access instead of exposing one flat index is close to what a RoPA-aware agent context layer needs to look like — scoped by data flow, not just by repo. Worth studying as a template before you let an agent read across your DPIA/RoPA/TIA libraries freely, and the vendor-only benchmark caveat is exactly the kind of claim your evals framework should flag before anyone builds a token-savings projection on it.

2

Not every evaluator belongs in the request path — Hamel Husain splits the decision into two cheap questions

Hamel Husain & Shreya Shankar, hamel.dev Evals FAQ — “Can my evaluators also be used to automatically fix or correct outputs in production?”

Yes, but only the subset that clears two tests. First, latency and cost: can the check run fast and cheaply enough in the request path without degrading the user's experience, or does it only work as an async, after-the-fact quality signal? Second, the error trade-off: weigh the cost of a false positive (blocking a good output and frustrating the user) against a false negative (letting a bad one through and causing harm) for your specific domain — medical advice should bias toward blocking, creative generation should bias toward letting through. Their rule of thumb is blunt: you would almost never put a slow, non-deterministic LLM-as-Judge synchronously in the request path as a guardrail.

Why it lands for you This maps directly onto which checks in a DSR or TIA pipeline should be blocking guardrails versus async evaluators — a DSR intake missing a required consent field should hard-block synchronously, while a TIA's qualitative risk narrative is exactly the kind of judgment call that should stay an async review rather than a synchronous LLM-judge gate whose false-positive rate you haven't actually measured.

3

Anthropic donates the Agent Skills standard to the same neutral foundation that already holds MCP

Simon Willison, simonwillison.net — “Donating Agent Skills to the Agentic AI Foundation”

On October 22, Anthropic handed the Agent Skills standard to the Agentic AI Foundation (AAIF), the Linux Foundation body it co-founded with Block and OpenAI and the same place MCP already lives. Anthropic frames the move as keeping skills “open, community-driven, and vendor-neutral” rather than a single-vendor format. Willison notes he predicted exactly this back in December 2025, when Anthropic first called skills an “open standard” — the donation isn't a surprise, it's confirmation of where the agent-tooling standards layer is consolidating.

Why it lands for you When a vendor hands a de facto standard to a neutral foundation, that's the signal to stop treating it as a vendor API and start treating it as the stable interface worth anchoring internal tooling to — directly relevant to the Copilot Studio vs. code-first agent governance tradeoff, since an AAIF-governed skill spec is a safer long-term dependency than a vendor-specific plugin format.

Paper of the Day

Research

Training the Whole Agent, Not Just the Model

Tang et al. · Zhejiang University (Bao) · arXiv 2610.28069 (cs.SE) · submitted Oct 20, 2026

What they foundCoding agents are usually trained by updating only the policy while the surrounding harness stays fixed — but RL training itself surfaces flawed repair strategies and interaction problems that shift as the policy learns. HarnessAdapt-RL trains the policy alongside two frozen teacher models: one writes task-specific skills targeting the mechanisms behind flawed repair strategies, the other evolves tools and hooks to fix recurring interaction problems, keeping any change only if it improves pass rate or trainable rate without hurting either. On a 9B base model it beats a GRPO baseline by 9.8, 12.6, and 6.4 percentage points on SWE-bench Verified, Multilingual, and Pro respectively, and also outperforms GRPO run on OpenHands' hand-designed harness. The skill gains persist even after the skills are stripped at evaluation time, but removing the evolved tools and hooks at deployment costs up to 7.7 points on Multilingual.

The move Don't freeze the harness during RL training and strip it wholesale at deployment by default — re-evolve tools and hooks alongside the policy as it learns, but test which pieces actually need to survive into production, because skills and tools/hooks don't behave the same way once removed.
Why it lands for you This feeds the self-evolving-harness governance question already on your radar: if the harness itself changes shape during training, your audit trail needs to capture which harness version produced which behavior at eval time, not just the model checkpoint — otherwise a “the model passed eval” claim becomes unverifiable the moment the harness moves on.

Repo of the Day

Try It

strands-agents/box

≈490 stars · 38 forks · Apache-2.0

Box runs an AI agent inside a sandbox that restricts exactly what it can execute, read, write, and reach on the network, combining OS-level isolation with default-deny “Dogwood” policies and credential injection that keeps secrets outside the agent process entirely — so a compromised or simply overzealous agent can't exfiltrate a key it was never handed in the first place. It's written in Rust, created October 2, and had commits land as recently as today — stats confirmed via a direct GitHub API pull, not a cached mirror.
